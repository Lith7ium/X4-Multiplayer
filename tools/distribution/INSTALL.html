New in this candidate

NPC damage across sectors, shared native kill contracts and reviewed Windows installer fixes are enabled. Use the complete matched pair and a new invitation. Two players per session; the host still runs X4. Guest HUD selection and occupied-pad behavior retain open findings.

Before starting

Use X4 9.00, Steam build23660954, and matching enabled official DLC including Timelines. Both packages include the server and Python runtime. Close X4 and the previous server, remove the old mod using its original REMOVE-MOD action (09 in7.3.1–7.4.1; 5 in7.3.0), then extract the complete new archive into a new folder.

Setup imports your normal display, sound and control preferences without changing that normal profile. Choose your usual profile if several are found. 08-IMPORT-SETTINGS repeats this copy later. Starts preserve custom resolution and bindings. The test profile uses borderless mode for background updates, with autosave=false and uisafemode=false. Resolution, graphics quality and controls are retained.

Host: create the shared world once

  1. Run 01-INSTALL, choose H and enter your reachable LAN/ZeroTier IPv4 address.
  2. Run 02-PREPARE-WORLD-HOST. X4 opens a disposable new world, saves it and closes automatically. Wait for Shared world ready. Do not play or load another save during preparation.
  3. Send JOIN-SESSION.json privately to the guest.
  4. Run 03-START-SERVER-HOST and keep its console open.
  5. Run 05-START-X4. The shared save loads automatically and your Shuttle appears after setup.

Guest: receive and load

  1. Keep the received JOIN-SESSION.json in your extracted package folder. Run 01-INSTALL, choose G and select the invitation in the file dialog if it is not already in this folder.
  2. Run 04-TEST-CONNECTION, then 05-START-X4.
  3. The launcher downloads and checks the host world before opening X4. Wait through automatic loading; do not select another save. Stay in the pilot seat until Shuttle setup completes.

Windows: use the numbered .cmd files. Linux: execute the corresponding .sh files; they open a terminal automatically. If your file manager opens an editor, choose Run/Execute or run bash 01-INSTALL.sh in a terminal. Keep the server terminal open.

Dedicated-server sets (with DEDICATED-SERVER.md): 01-INSTALL does not ask for a role. The Linux package is the server; every client package (Windows11[-GuestK] or Linux-Client[K]) follows the guest steps. Each client slot has a Windows and a Linux package; use the one for your OS.

Numbers identify actions: guests skip HOST-only actions 02 and 03. Optional checks/removal are 06–10. Detailed evidence is grouped under reports/.

Background operation and teleportation

Alt+Tab to another application while X4 stays open in borderless mode. Keep the server running. Explicit pause or minimizing to the desktop can still suspend native updates. All four personal teleportation research levels are unlocked after Shuttle setup; use normal map/context-menu destinations. HQ relocation is separate.

Network and roles

Allow UDP45841 and TCP45844 to the host on the private test network. The connection check uses UDP; world transfer additionally needs TCP. A working ZeroTier connection needs no router forwarding. Keep the firewall enabled. The host must run both X4 and the included server; the Python server alone does not simulate X4.

Restart, diagnostics and removal

For every retry stop both games and the relay, then restart the relay and both games. Both reload the same starting save; progress from the previous attempt is not resumed. Use a fresh extracted pair and invitation for a different world. Preparation will not replace an existing world.

Read NEXT-TEST.txt and HUMAN-NPC-MISSION-TEST.txt for the new cross-sector NPC damage and shared native kill-contract checks. Run 06-DIAGNOSTICS on both PCs before restarting after a mismatch. Earlier accepted cargo/radar/movement checks need repetition only if a new symptom appears.

Run 06-DIAGNOSTICS on both PCs before restarting after a failure. Include roles/OS, approximate time, sector and station code. Keep private session files out of public reports. 07-VERIFY-PACKAGE checks package files; configured role files are checked separately.

Close X4 and the relay, then run 09-REMOVE-MOD from its owning package. Only the recorded, byte-matching save_010 copy in profile45841 is removed; the package retains its immutable world bundle and archives its mod. Other or changed saves are preserved. Never load or save normal campaigns in this test profile.

Content differences and limits

Different DLC/mod sets stop shared-world loading. No Workshop selections are rewritten and the withdrawn7.2 isolation helper is not included. A separate profile alone does not isolate the Steam account. Compare content manually if the launcher reports a difference.

Saved station-pad reservation and native attachment now have local engine evidence. Normal peer-ship boarding and the two-native occupied-pad crash regression still need human acceptance. Stop if both games grant the same occupied bay.

Station construction/destruction and economy are not continuously synchronized. NPC combat is limited to free-flying S/M hull/shields with the supported stock guns. Shared normal missions cover one standalone kill-contract family; guest offers use [Shared]. Other mission families, fleet/capture commands, persistent campaign resume, ingame text chat and dedicated hosting remain unfinished.
