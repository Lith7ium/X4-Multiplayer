LOCKSTEP CENSUS SCENARIOS: MISSIONS, HIGHWAYS, OTHER PLAYER STARTS
29 October 2026 | built and unit-tested (LuaJIT probe, MD schema, tooling); not yet run live

Three stress fixtures for two-client census runs (reports/LOCKSTEP-CENSUS-20261028.txt),
in the style of native_gate_bigbattle.xml and native_gate_tour.xml: the probe raises MD
cues at fixed gated ticks on every client, nothing depends on player input. Every log
line is "[X4LAN] NATIVE_GATE MISSION|HIGHWAY ..." and prints no runtime IDs, so the
client logs can be compared line by line:

  python tools/dev/native_gate_scenarios.py compare <run>/client1/x4lan-debug.txt <run>/client2/x4lan-debug.txt

The census tools (census_world/events/scripts) remain the divergence evidence; the
scenario lines show what the fixture did and where the clients' stories split.

ADDING A SCENARIO TO A FULL-STACK OVERLAY

  python tools/dev/native_gate_scenarios.py overlay missions --base .local/census/overlay-Long4 --out .local/census/overlay-Mis1
  python tools/dev/native_gate_scenarios.py overlay highway [--mode fly] [--super] [--target beacon] \
      --base .local/census/overlay-Long4 --out .local/census/overlay-Hw1
  .local/census/run.sh mis-M1 .local/census/overlay-Mis1 b1,b2 1800

The overlay command copies the base, installs this checkout's probe, copies the MD into
md/, replaces any earlier scenario block, appends the config lines and rewrites
x4lane-manifest.json. --gate-dll installs a rebuilt gate DLL; --gravidar-watch SAVED_ID
(repeat, up to 8; needs native_gate_gravidar_key_all in the base) adds the read-only
Gravidar contact watch, compared with "python tools/dev/census_gravidar.py <run>";
--speech-game-time adds native_gate_speech_game_time (needs a gate DLL from this branch);
"overlay none" strips the scenario for a control run. It refuses bases without the battle snapshot boot and bases with
options the fixture excludes. By hand: copy tools/dev/native_gate_missions.xml or
native_gate_highway.xml into <overlay>/md/ and append the lines printed by
"native_gate_scenarios.py config missions|highway ...":

  -- missions (relay ticks 1800)
  X4LAN_CONFIG.native_gate_missions = true

  -- highway, warp to the entry (relay ticks 1500; 2700 with the superhighway stage)
  X4LAN_CONFIG.native_gate_highway = "warp"
  X4LAN_CONFIG.native_gate_highway_super = true         optional
  X4LAN_CONFIG.native_gate_highway_target = "beacon"    optional fallback, see below

  -- highway, fly there without any warp (relay ticks 3000; 4500 with --super)
  X4LAN_CONFIG.native_gate_highway = "fly"

The probe refuses (before boot): values other than those above; either scenario without
native_gate_hash="battle" and a snapshot boot; missions together with highway; either
with native_gate_player_tour; highway with pilot inputs, player probes or player orders
(the highway fixture flies the player ship by autopilot). war (native_gate_big_war) and
the docking/commands fixtures combine freely; keep native_gate_big_spawn off for the
missions scenario (its ships may kill the mission targets early). At tick 1 the probe
logs "NATIVE_GATE SCENARIO missions=... highway=... super=... target=...".

Randomness and player/UI state in the mission systems (from gamescripts, read-only):
- GenericMissions manager: offer stations by .random, SelectMission delay [50 ms, 4 s],
  weighted random GM and variant choice (SelectMissionVariant), mission count depends on
  player.hasactivemission and player.sector; re-evaluates on player sector change and
  every 10 min.
- Offers: create_cue_actor builds the client NPC (generated name/appearance); object
  offers time out after a random 8-12 min (beyond these runs); RemoveDueToDistance
  and the offer timeout read player.entity distance/zone; OfferDiscovered waits for
  event_player_discovered_mission_offer (player radar/UI discovery).
- Accept: stock voice line (speak actor=$Client), logbook entry, stat counters; the
  briefing/holomap/cutscene cues only react to UI briefing events (not used here).
- LIB_Reward_Balancing: reward credits (fixed here), additional ware rewards and
  notoriety are random draws.
- Mission guidance (set_objective, player.activemissionwaypoint) is player state; the
  active mission is chosen by create_mission/UI.

HIGHWAY (tools/dev/native_gate_highway.xml, native_gate_highway = "warp" | "fly")

Local highway: Highway02 of Argon Prime (cluster_14_sector001, the snapshot 005 start
sector), 230 km from Zone001 (entry, sector z = -110 km) to Zone003 (z = +120 km), x =
50.5 km, y = 0 (maps/xu_ep2_universe zonehighways.xml + sectors.xml). Argon Prime has no
superhighway; the optional stage uses Grand Exchange I (cluster_01_sector001), whose
superhighway gate to cluster_01_sector002 is picked by destination, not by find order.

tick 40     HighwayStart: "warp" warps the player ship 3 km above the entry gate (fixed
            point, yaw 0, no safe-position search); "fly" requires the player already in
            Argon Prime and does not move it. Spawns a convoy next to the player (Argon S
            fighters 9801-9803, M transporter 9804) with precise MoveWait orders to 3 km
            above the far end, so native pathing (uselocalhighways) routes them through
            the tube, and two beacon scouts beside the tube (9901 half way, 9902 far end).
tick 100    HighwayEnter: start_player_autopilot (stock move.autopilot, useunknown) to the
            highway itself; the autopilot enters it and leaves full throttle. With
            native_gate_highway_target = "beacon" it targets the far beacon instead and
            the native path decides whether to use the tube (fallback if a highway is
            not accepted as autopilot destination).
tick 930    HighwayLeave ("fly": 2430): autopilot to the half-way beacon, which leaves the
            tube mid-way.
tick 1230   HighwaySuper ("fly": 3030), optional: stops the autopilot and warps the player
            5 km above the Grand Exchange I superhighway entry gate.
tick 1290   HighwaySuperEnter ("fly": 3090): autopilot into that superhighway (target
            "beacon": to a scout spawned 5 km above its exit gate, seed 9903).
every 60    HighwaySample (from tick 120).

A "refused=..." setup line means the run did not exercise the highway (wrong sector in
"fly" mode, or the highway/gate lookup failed); "local=0" in every sample after tick
~300 means the autopilot did not enter the tube: rerun with target "beacon".
With target "highway" (sc-highway) the player entered the tube at tick 703 and dropped out
14 ticks later: move.autopilot ends on arrival and sets the throttle to 0. The leave
autopilot to the half-way beacon then rode the tube at 13 km/s. Prefer target "beacon".
Player-side diagnostics (added after sc-highway): entity_zone (player.entity zone change)
and activity (player.entity startactivity/stopactivity/activitycharged) lines with game
ms, and activity=/entityzone= in every sample.

OTHER PLAYER STARTS (one imported snapshot per gamestart)

How snapshot 005 was made: tools/dev/native_gate_lane.py --capture-snapshot wraps one
disposable lane run (x4lane run, -module custom_creative -seed:276944566) with overlay
snapshot-capture-overlay-v4 = native_gate_battle.xml + x4lan_fixedtick_64.dll +
native_gate_snapshot.lua. At game time 5 the script raises Spawn (player ship warped to
0/100 km/0 of its sector, the seeded 12-ship fixture around it), checks all 12 actors
are at nearby attention, pauses and saves save_009, which the wrapper collects into
<collect>/native-snapshot/save_009.xml.gz and removes from the lane profile.

The battle MD only spawns in custom_creative, and its file hash is pinned by the portable
(Linux) import contract, so it is not edited. The capture overlay for another start gets
a copy whose only change is that gamestart guard; census runs on the captured save then
use the unmodified battle MD (the Spawn cue is already complete in the save).
native_gate_snapshot.lua now also waits while a fullscreen cutscene runs and, with
native_gate_snapshot_gamestart set, refuses a lane that started another gamestart.

  python tools/dev/native_gate_scenarios.py starts
    recommended: x4ep1_gamestart_fight    base game, Paranid fighter, cluster_47 (map-uncover script only)
                 x4ep1_gamestart_terran1  Terran fighter, cluster_101, gs_terran1 plot (wingmate, satellites, plot missions)
                 x4ep1_gamestart_split2   Split fighter, cluster_421, gs_split2 plot
    also allowed: x4ep1_gamestart_discover, custom_creative
    refused: starts on foot or docked (trade, scientist, boso, intro, tutorial, terran2,
             pirate2, boron2), spacesuit (split1), fullscreen plot cutscene (boron1, pirate1),
             Timelines/tutorial galaxies.

Per gamestart <id> (coordinator; X4 closed, lane admission as usual):

1. Capture overlay (reuses the capture-005 fixed-tick DLL):
     python tools/dev/native_gate_scenarios.py capture-overlay --gamestart <id> \
       --fixedtick-dll .local/native-lockstep/snapshot-capture-overlay-v4/native/x4lan_fixedtick_64.dll \
       --out .local/native-lockstep/snapshot-capture-overlay-<id>
2. Capture (one lane; same arguments as capture 005 plus --gamestart):
     python tools/dev/native_gate_lane.py --lane-tool ../lanes/release-5d5a680ec6ef/dev/x4lane.py --capture-snapshot -- \
       run --agent native-lockstep --label native-snapshot-<id> --timeout 420 --wait 180 --settle 2 \
       --base .local/lockstep-live/frozen-v3/src/extension/x4_lan_lab \
       --overlay .local/native-lockstep/snapshot-capture-overlay-<id> --gamestart <id> --seed 276944566 \
       --until "NATIVE_SNAPSHOT SAVED" --expect "NATIVE_SNAPSHOT SAVE_REQUEST" --expect "NATIVE_SNAPSHOT GAMESTART id=<id>" \
       --fail-on "NATIVE_SNAPSHOT ERROR|Error while executing.*native_gate_snapshot|Error in MD cue md.X4LAN_NativeGate" \
       --collect .local/native-lockstep/snapshot-capture-<id>
   Result: .local/native-lockstep/snapshot-capture-<id>/native-snapshot/save_009.xml.gz
   (treat it as read-only like snapshot 005). A NATIVE_SNAPSHOT ERROR "requires all 12
   actors at nearby attention" means the start's scripted camera kept the fixture out of
   attention: retry once; if it repeats, the start is unsuitable.
3. Bind a census overlay to it (read-only on the save; prints start, player ship, sector):
     python tools/dev/native_gate_scenarios.py snapshot-info .local/native-lockstep/snapshot-capture-<id>/native-snapshot/save_009.xml.gz
     python tools/dev/native_gate_scenarios.py rebase --base .local/census/overlay-Long4 \
       --snapshot .local/native-lockstep/snapshot-capture-<id>/native-snapshot/save_009.xml.gz \
       --out .local/census/overlay-Long4-<id>
   rebase rewrites native_gate_snapshot_sha (sha256 of the .xml.gz bytes, which
   native_gate_lane.py --snapshot-in checks against the staged file),
   native_gate_snapshot_fixture (the 12 saved IDs of X4LAN_NativeGate Spawn.$ships, via
   build_native_gate_overlay.snapshot_fixture) and native_gate_world_hash_watch (the 12
   fixture IDs plus the player's ship; the snapshot-005 watch list means nothing in another
   save). It refuses bases with snapshot-005-specific GetUp/NPC pilot options.
   Applied to snapshot 005 it reproduces the committed sha 7816351056e6... and fixture IDs.
4. Run: .local/census/run.sh hard-codes --snapshot-in to capture 005; use a copy that
   takes the save as a fifth argument (--snapshot-in "$5"), e.g.
     .local/census/runStart.sh start-fight-S1 .local/census/overlay-Long4-x4ep1_gamestart_fight b1,b2 600 \
       .local/native-lockstep/snapshot-capture-x4ep1_gamestart_fight/native-snapshot/save_009.xml.gz
   Scenario overlays stack: rebase first, then "overlay missions|highway --base <rebased>".
   The highway fixture always rides Argon Prime's highway; in "warp" mode it warps there
   from any start, "fly" mode refuses outside Argon Prime.

SPEECH ON THE GAME CLOCK (native_gate_speech_game_time = true, default off, stop 120)
EntitySpeakData::Tick (563d30) completes a line either on the state5 audio-finished
path, when the audio source reports finished (wall clock), or on the state4 deadline
path at start+duration on the game clock. The mode reuses the NPC deadline
experiment's patch (thunk 1344, CAS at 563e80, whole-function pin) and routes every
eligible audio-finished completion, of any speaker, to the deadline path: state5,
timer/interruption flags clear, actual audio duration (+0x110) equal to SpeakData+0x18,
finite positive duration, finite start, game clock >= start. The speaker's portable
key is recorded only. A flagged line keeps the native path (flagged= in the status);
unreadable or inconsistent state is a failure and stops the gate with reason 120.
The probe arms it before the load (re-arms the owned patch after the loading-UI
reload) and logs SPEECH_TIME_ROW (tick, key, page/line, duration/start/clock bits,
early=1 when the audio finished before the deadline), SPEECH_TIME status lines and
SPEECH_TIME_STOP. Residual case: a client whose audio becomes ready only after the
game deadline still ends on the initial estimate through native state5; its line is
then not in SPEECH_TIME_ROW. Not yet run natively.

WHAT IS EXPECTED TO DESYNC (hypotheses for the census, not results)
- Missions: generic offer generation creates cue actors and MD cue instances at runtime
  (unmapped script owners; check script_rng_unmapped rows), the accept voice line (NPC
  speech selection was nondeterministic before), notoriety/relation changes after kills,
  and whatever the two accepted generic missions spawn (create_ship without seed, safe

  traffic, running story plots with timed dialogue and plot missions (terran1, split2),
  and possibly other load-created sectors in the Gravidar order (AI_SCHEDULE_FALLBACK).
