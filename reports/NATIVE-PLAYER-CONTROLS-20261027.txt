NATIVE NEGATIVE EVIDENCE

Two disposable native games loaded identical pristine snapshot bytes. Their
saved player, occupied ship and actually controlled ship identities matched:
both copies controlled the SAME saved ship. This is an observed limitation,
not a method for representing two players.

At shared UI tick 30, one client invoked the native cockpit flight-assist
toggle export, the other the native travel-start export. Flight assist changed
from enabled to disabled only on the first client. The travel call issued its
native event but the same-tick activity remained none; this does not prove that
travel became active. The appended singleton state caused an immediate mismatch
at tick 30. Both gates stopped/restored at 30 with zero wait-clock movement.
The released lane runner restored both disposable profiles and snapshot slots.

Independent reconstruction verified all 62 declared hashes, both singleton
contexts, exactly one local action per client and the mismatch boundary. A
focused player evidence check is valid negative evidence; session_pass is false.
The existing full validator remains evidence_valid=false because the intentionally
short run did not exercise its configured spline, velocity and tactical-command
checks. Those checks were not relaxed. Raw logs/saved IDs remain private.

NATIVE CONTROL FINDINGS

The Lua live adapter previously queued only fixed-width tactical commands into
Mission Director create_order actions. It did not capture keyboard, mouse, aim,
continuous flight, cockpit button edges or independent native player state.

Read-only exact-build analysis identifies PlayerController::SetControllerValueID
at RVA d8fb60, called by the native input dispatcher at d95180. Several input
channels, including throttle, write process-global state rather than only the
controller instance. The MD playership throttle action reaches the same throttle
state after checking the singleton. The PlayerController transform evaluator
at d8a680 also consumes global state and caches results by game time.
The native PlayerShootController trigger evaluator at 7e8bc0 reads global
primary/secondary trigger bits and the singleton's activity; its 7e8e60 helper
consults global input-system state. Merely giving two ships separate shoot
controller objects would not isolate those firing inputs either.

The native controller getter at 9fc550 resolves the single Universe player,
occupied control post and controller chain. Switching one player pointer or
calling the setter twice therefore does not establish two independent contexts.

BOUNDED PLAYER-CONTEXT DEPENDENCY INVENTORY

The following exact-build static findings identify shared state requiring
isolation. This is a direct-function inventory, not a complete transitive graph.
Indirect calls, event consumers and other threads still need observation.

* Input update d95180 checks the controller's last update time at +f0, consumes
  process input state, and updates that timestamp plus cached transforms. Its
  device/mouse channels occupy parts of 2f4b720..2f4b7fe, with additional input
  timers at 31c1fd8 and global mode flags. A second call at the same game time can
  take the cached branch; copying only axes cannot reproduce independent input.
  Before sampling, it resolves the singleton player's parent and requires that
  component equal global 6b661e8; shared reentry guard 38f4db4 also blocks it.
  Separate controller allocation alone cannot satisfy this native context check.
* PlayerController slot 33, d97e80, selects desired throttle at 2f4b760 and writes
  smoothed throttle at 2f4b764 using TLS game-time deltas. Sticky full throttle
  retains time/value at 2f4b830/838. Feedback retains flags/timers around
  2f4b848/850 and 2f4b858/860 and resolves the global occupied ship. Match-speed
  state also has per-controller target/time fields. Config values are separate
  from mutable player state; they must not be blindly copied with an address span.
* Transform evaluator d8a680 reads a per-controller time-keyed cache rooted at
  +2a0/+2a8, current/previous transforms, +f0 time and interpolation history near
  +19330..19378. It also branches on global 2f4b7d8, 2f4b828 and 6b661d0. The
  native slot 34 path d98e50 clears/rebuilds portions of that cache/history and
  updates shared mode/effect state. A second context needs its own cache lifetime.
* Shoot evaluation 7e8bc0 consumes four global trigger bits at 38f0728..72b and
  singleton activity +6ab4. The controller owns held/group bytes +a0..a2, a
  fractional firing accumulator +a4, and an additional timer +b0. Aim evaluation
  7e8650 consults global aim modes 2f4b9c0/9c4, device mode, singleton target
  +6c88 and aim data +6c60..6c80. Trigger input alone is not a firing context.

The observer covers slot 33 and shoot slot 14 with full function pins,
original-call-once wrappers and owned restoration. Enabling at the first admitted
UI boundary explicitly leaves load-time and earlier updates unobserved. No global
player pointer switching or second-context mutation is justified by this inventory.

IMPLEMENTED SAFETY AND SHARED INPUT BOUNDARY

The experimental agreed-singleton plan uses native gate wire version 2. A
proposal made at tick N-1 is admitted for the UI boundary following simulation
tick N. The resulting native simulation effect may begin at N+1; this delay is
explicit. Each admitted batch validates both slots before any native action.
Ticks must be contiguous and cannot be applied twice. Context 1 belongs only to
logical player 1. Player 2 native actions are refused until an independent
context is implemented. The saved player/container/occupied/controlled identities
are bound and rechecked immediately before writes; transfer fails closed.

Reserved native opcodes are 81 (assist toggle), 82 (travel start), 83 (travel
stop), 84 (throttle), 85 (primary trigger edge), and 86 (native target selection).
Byte 2 is context 01; byte 3 is zero except throttle (-1..1 as integer 0..200),
trigger (0/1), or fixture-scoped target (1..12); byte 4 is reserved zero.
The existing authenticated loopback barrier carries the canonical slot order.
Tactical and singleton plans are exclusive until a shared dispatcher can validate
all action families before any mutation. Management experiments reserve 40..4f.

The throttle API calls the complete SHA-pinned native setter once after validating
the current player controller, saved actor, owner, shared tick and finite bounds.
It patches no code and creates no proxy. Raw native axis bits and player position
are sampled for the throttle experiment. This still does not capture every
device input, weapon/aim state or every player-controller cache.
The throttle path has native convergence evidence above plus C/Lua refusal and
once-only tests. A separate conflict plan submits both players against context 1
and rejects the entire batch before even the authorized first action runs, as
verified above. The current C check and 90 focused Python/Lua/UDP checks pass.

REMAINING REQUIREMENTS

True independent native contexts need isolation or generalization of global
input channels, player entities/control posts, controller history and cached
transforms, activity/target/camera/aim, weapon groups and held-button edges,
autopilot/docking, inventory/account/faction authority and player-dependent MD/AI.
Player-specific radar/attention behavior also depends on the native singleton.
Complete input records need shared epoch/tick, owner/context, monotonic sequence,
stable actor/target identities, exact axis values and button edges, with duplicate,
late, conflicting or unsupported actions rejected before effects.

Any desync remains a stop. No hash suppression or unproven resume/repair is added.
Full-world divergence and identities for newly created objects remain separate
open requirements. Actual native player firing/damage is observed above, with a
projectile initialization desync retained and rejected and a separately tested
launch RNG scope that corrects this bounded sequence. Native keyboard/mouse,
independent aim/fire/boost, independent docking and two independent player
entities are not accepted by these diagnostics.
