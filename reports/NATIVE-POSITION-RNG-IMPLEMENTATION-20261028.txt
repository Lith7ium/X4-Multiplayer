IMPLEMENTATION

The new lockstep_world_position_rng*.h files own admission, finite input/pin
checks, the single seed store, restoration and export. Default-NULL callbacks
in the existing Position wrapper run after raw pre-capture, around the existing
sampler original, and in outer finally after raw post-capture. The per-scope
sample/finally pointers are retained at entry. A changed global callback cannot
silently remove cleanup; it instead produces a failed receipt.

Before any write, the helper requires the exact native owner/order/import and
completed Find binding; selected Action/node/program/phase; zero base; kind 0,
coordinates 0, absent space/reference, range kind 2; evaluated minimum 0,
maximum/difference 50000; distribution/count 1; exact caller frame and RNG
argument; required FP controls; and supported stable math dispatch flags.
The full reviewed functions, direct calls and constants are pinned, with only
verified owned Position patch bytes reconstructed. Evaluated maximum T+0x78
and result scratch T+0x178 are read from the actual incoming sampler frame.
Ignored padding remains local raw evidence and never enters the key.

Seed admission and STOP closure share wpr_lock. Caller state is copied, then
write_attempted, restore_required and debt are set BEFORE the guarded store.
Only successful exact readback marks applied. A partial/faulting/uncertain store
therefore still owns restoration. A true pre-write refusal leaves native RNG
behavior intact and does not restore a saved state. No lock spans the original.

The engine sampler executes once. The native radius continuation and two
direct direction draws execute normally. No radius, direction, transform or
return value is replaced. The inherited raw Position post-capture records the
actual scoped endpoint. The new finally then conditionally restores the exact
caller TLS location before wp_outer_finish publishes completion/open counts.
STOP closes admission before stats.active clears and before hook restoration.

Normal and abnormal cleanup revalidate the retained thread, TLS provider,
address, alignment and writable storage. Store/readback and provider faults
are contained in cleanup; the original foreign exception still propagates.
Abnormal cleanup does not read unwound Value/native object frames. Changed TLS
or unsupported restoration retains explicit debt. A successful restore never
clears STOP, nesting, identity, postcondition or exception errors.

The existing Find/Wait conflict seam rejects nested intervention while this
scope is present. The existing raw Position schema 2 remains byte-for-byte the
same. It remains natural-only when the new option is absent.
