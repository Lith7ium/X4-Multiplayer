RANKED CONTROL-ADMISSION MEASURES; DESIGN ONLY

1. For a passive handoff candidate, observe neutral native requests over an
   agreed contiguous interval. Check all six values, caller/axis/order, epsilon,
   gains, controller modes, target/history and publication at the actual request
   boundary. The current observer can diagnose this passive condition, and the
   observed candidates fail it. This is NOT a universal prerequisite for real
   player takeover: native AI may keep making idle microcorrections forever.
   An active native authority transfer must instead suspend or replace its
   producer, with actual completion evidence. The follow-up in
   NATIVE-PLAYER-TAKEOVER-TRANSACTION-20261027.txt identifies such native stages.
   No timeout or epsilon-sized forced zero should manufacture neutrality.
   Even matching passive neutrality is historical evidence, not future exclusion.

2. Account for the detached manager list and every admitted command through
   typed dispatch completion. A passive lease would require no pending generation;
   a native active handoff may retain dormant orders and therefore needs proof
   that those producers cannot regain publication authority while leased. The
   consumer releases the producer lock before its private-list dispatch, so an
   empty shared head and empty Agent queues do not prove drain. World-motion's
   typed dispatch observer is the appropriate next evidence source. Abort and
   direct Set commands alter flags without passing through pending append;
   formation/import/copy writers also remain. Full producer exclusion during
   the leased interval is unproved. A counter of selected AddTargetPoint calls
   alone cannot authorize a lease, and no arbitrary engine lock should be held
   across solver calls to simulate an exclusive phase.

3. At admission and application, require the same full native ID/generation,
   true owner, exact type/macro and component/controller/Agent/model/solver
   relationship. These are feasible fail-closed diagnostic guards. They are
   NOT an atomic ownership/lifetime transaction: ced70 retains no reference,
   the16-bit generation can wrap, child allocations have no verified generation,
   and SetOwner writes before its notifications. The missing stronger proof is
   a reviewed native lifetime mechanism or execution interval excluding relevant
   destruction, child replacement and owner mutation. Repeated reads cannot
   supply it. Retaining only component memory would not automatically freeze
   its owner or controller/model/solver children.

4. After the applicable passive or active authority proof, prepare a handoff ticket
   with agreed epoch/tick, two distinct saved assets, native generation and owner,
   logical-slot capabilities, lifetime evidence and input revision. Both copies
   must explicitly acknowledge the same complete ticket before a later shared
   application tick. Decode both input slots and all tactical/management families
   before any writer; reject conflicting asset operations. A future receipt must
   distinguish reservation, actual native request application and publication.
   Missing input holds the barrier; stale/duplicate/gap input is refused. A
   preflight change denies both slots. Any failure after a partial native effect
   poisons the tick, emits partial evidence and prevents ACK/resume/retry; no
   invented rollback or peer-state correction is allowed.
