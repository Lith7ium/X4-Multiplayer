WINDOWS KEYS MATCHING THE LINUX GATE
30 October 2026 | For one run: Windows limited to what the Linux gate has, 60 Hz, compared with a Linux run.

WHY
Windows' full stack keys draws Linux does not key yet (script RNG, the actor keys), so the streams part at the
first keyed draw and say nothing about the platforms. With only these keys, both sides run the same modules.
The two clients of each side give that side's noise floor: Linux had 47 differing objects at tick 60 in run
vps-linux-11, so a difference between the platforms before about tick 60 is the platforms.

THE LINUX SIDE
Bundle 15 (run vps-linux-12), or any later bundle with the same options:
  linux_gate_live.py bundle --portable-math --seed-rng --path-determinism 3 --region-rng key --ai-wait-rng
    --md-resume-rng --boot-hold --event-order --event-rows 120 --gravidar --gravidar-deadlines --travel-snapshot

THE WINDOWS CONFIG
native_gate_ai_diag and native_gate_radar_diag are not on the Linux side. They are read-only traces the Windows
gate requires under native_gate_radar_serial, and they arm nothing else. Linux reaches the same floating point
state with its portable math preload; the four FP keys are the Windows side of that.
Windows needs the same snapshot, the same watch list and 60 Hz: no tick_hz, path_budget, pass stride or fast reads.

WHAT IT CANNOT SHOW
Not matched on both sides, so expected to differ between the platforms:
- Physics: X4.exe's Jolt is not redirected (the W1-W5 plan), so anything physics decides can part for that reason.
- Created identities: a local source ranks by runtime ID. Runtime IDs differ per client until set mode is on both.
- Runs of the census at stride 60 only show when a difference is older than its capture.
