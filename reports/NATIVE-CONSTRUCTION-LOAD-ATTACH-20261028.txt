INITIAL SETUP AND ATTACHMENT

Both first configurations remain phase0-only. ACK2's immutable prepared binding
is created under creation_lock after the existing common guards and successful
CNG, with valid published last. It binds exact image/UI owner, native boot start,
slot, port, secret, digest, options, epoch, manifest, mode and local nonce. This
record is prepared identity, not successful attachment or native lifetime lease.
CNG does not consume game RNG. ACK1 retains its original nonce generation point.

Only an already configured healthy session may attach in native phases1..3.
Every attachment rechecks immutable binding, zero issued/selected activity,
records/open scopes, failures/restoration debt, installed pins/composition and
STOP/closing. No state or cursor is reset. First/reattach comes from the native
ordinal, limited to8. Phases cannot regress. Registry attachment requires its
ordinal equal the RNG ordinal; it advances once. RNG then requires the registry
ordinal exactly one greater before committing its own acknowledgement. Without
registry, the registry counter must remain0. A half-pair cannot be repaired by
another registry call. First RNG initialization after LOAD_REQUEST still refuses,
even when an initial registry claim exists. Refusal retains counters, keys and
nonce; public configuration refusal stops the gate as before.

Creation and registry locks are acquired separately. Registry copies and checks
the prepared boot binding under creation_lock, releases it, then commits under
registry_creation_lock with fresh STOP/active/no-activity checks. Configuration
is restricted to the exact UI owner; foreign calls cannot poison its binding.
The final native accepted phase is captured, not replaced with a caller value.
Registry phase may precede RNG phase during natural1-to2-to3 progress. These
numbers describe boot state, not proof that all game loading has completed.

EVIDENCE AND FAILURE RETENTION

ACK2 rows have this exact field order:
  schema ordinal boot digest slot phase registry_phase reattach registry_acks
  issued state records scopes attempted
ACK2 footer:
  schema acks registry_acks boot digest slot phase registry_phase failed
The parser requires matching configuration/ACK pairs, one exact snapshot
LOAD_REQUEST between initial and subsequent attachments, monotone phases,
matching boot/digest/counters and ordered final closure. Partial pairs fail.
The existing registry observation schema1 remains unchanged and separately
validates registry-config/RNG-config/ACK ordering and cardinality.

The probe creates both protected drain closures before attempting registry or
RNG configuration. It still activates registry first. Thus a registry refusal
does not prevent the abort handler from draining already resident RNG evidence.
Each Lua activation saves its returned receipt; a logging interruption resumes
that receipt without invoking native configuration again. Native scope rows,
keys, late-update refusal, bind semantics and no-publication policy are unchanged.
