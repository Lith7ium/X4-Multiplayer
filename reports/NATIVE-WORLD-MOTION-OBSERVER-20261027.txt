READ-ONLY IMPORTED-WORLD MOTION OBSERVER

Purpose
-------
The previous world-prebind-006 and -007 experiments matched every imported-world
root at frame 1. Frame 2 differed only in motion, including saved ship 9d39b.
Both clients had the same physical buffer phase during the compared scans.
That evidence requires locating an actual input or update difference, rather
than relabeling buffers or correcting the final transform.

This optional observer traces the existing native Ship::Move, navigation Move,
Agent update, steering update, and spline update wrappers for selected imported
saved identities. It adds no patch site and calls no native getter. The complete
pinned Windows EXE_SHA validates the layouts; each existing wrapper retains its
own installation signature. Only navigation controllers with validated raw
owner/agent relationships and recognized steering/spline/linear models are covered.
The observer does not register, seed, refresh, initialize, or move watched ships.
Fixed fixture actors are refused by the trace API.

Configuration
-------------
Use --world-trace-ticks 12 with --world-identities, --world-hash-stride 1,
--serial-pathing and one or more --world-hash-watch SAVED_ID values. The builder
enables the existing diagnostic hooks. Existing fixture interventions, if
separately selected, still affect only their fixture actors.

First-frame world capture retains the exact resolved object/runtime identity
for each watch. Arm follows that capture, takes one read-only baseline, and
records native calls from frame 2 through the requested final frame (2..12).
There are at most 64 watches and 2048 events. No event buffer is reused while a
native callback could retain it; memory remains allocated until process exit.

Evidence
--------
Each event reserves its own record atomically. Thread-local parent tokens retain
nesting. Records become visible only after complete publication. Both entry and
exit validate the raw object/runtime/controller/agent lifetime. The original
call still runs exactly once if any observation fails.

Before/after snapshots record TLS RNG/time/view, cheap/player/dt/time arguments,
both physical navigation banks, all three parameter buffers, Agent+4e0..ad0,
the active model, the steering/spline slot argument, controller refresh fields,
Agent+ac0 timer/+ac8 setup byte, and the manager's budget/completion fields.
Every snapshot includes active/other selectors before and after its raw reads.
Model/timer evidence does not establish which field causes the divergence.
In particular, the consumer of the constructor-randomized +ac0 timer remains
unproven. Raw blocks contain pointers and padding and are not portable hashes.

WORLD_TRACE_EVENT, WORLD_TRACE_STATE, WORLD_TRACE_DATA and WORLD_TRACE_STOP are
append-only supplemental records. The existing WORLD_IMPORTED_1 hashes and
their object coverage are unchanged. A missing event/phase/block/stop record,
read or lifetime failure, unsupported model, changing bank phase, bad parent,
overflow or unmatched entry/exit fails trace coverage. Same-object updates
overlapping on different threads are retained as unsupported causal alignment.
An unexercised hook remains visible in the coverage counts, never a success
claim for that hook. Native paths outside these five wrappers remain unobserved.

Use tools/dev/compare_native_world_trace.py LEFT_LOG RIGHT_LOG --out RESULT.
Matching uses saved identity, tick, hook, occurrence and nested parent identity;
process/thread IDs and cross-object global order are not comparison keys.
Interpreted scalar/vector differences are separate from raw local differences.
Runtime references and vector padding are retained only as raw diagnostics.
The regular gate validator also rejects incomplete/failed configured traces.

Validation before any native run
--------------------------------
The Windows C harness checks read-only snapshots, nested publication, concurrent
worker reservations, raw bank labels, lifetime failures, missing TLS, the early
tick limit, and overflow. Python tests cover incomplete/tampered evidence,
thread-independent causal matching, concurrent-owner rejection, separate input
and output differences, and raw-pointer/padding separation. LuaJIT checks that
arming follows capture and that append-only records are drained exactly once.
No live-game success is claimed by these tests.
