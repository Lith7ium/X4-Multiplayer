LOCKSTEP DIVERGENCE CENSUS - 28 OCTOBER 2026

WHY A CENSUS
The strict barrier stops at the first differing tick, so each live run exposed
one divergence source. World011-017 all stopped at tick 2. A census run keeps
both clients running (relay --observe) and compares every world capture, every
delivered event and every RNG stream, so several sources are found per run.
Measured on two native Windows clients, same PC, imported save snapshot 005,
60 ticks. Divergence counts are noisy run to run; two runs per configuration.

TOOLS (tools/dev)
native_gate_relay.py --observe   record mismatching ticks, keep releasing frames
census_world.py <run>            first differing capture per imported object,
                                 grouped by parent into root candidates
census_threads.py <run>          per-thread TLS RNG words (THREAD_RNG), draws per
                                 frame via rng_steps.c (X4 LCG + rotr30 step)
census_jobs.py <run>             per-JTM-job draws (native_gate_job_rng observe)
census_events.py <run>           delivered due-event multisets per tick
census_scripts.py <run>          per-script RNG rows joined by portable key
.local/census/run.sh             two-lane runner wrapper (not committed)

FINDINGS, IN ORDER OF DISCOVERY
1. Nav refresh timing (pathing determinism, f60cd8b + 35fcae1): low-attention
   ships were stamped whenever some code queried their position. Deterministic
   per-frame stamping by saved ID cut divergence from ~280-480 to ~60-140
   objects at tick 10 and from ~1,750-2,000 to ~300-370 at tick 60.
2. JTM pool jobs make zero RNG draws (J01); per-job keying (9269fc3) is
   retained as an opt-in census but has no measurable effect.
3. Boot RNG anchor: UI-thread stream differs before the first post-load action;
   draw counts from an identical anchor differ by a few (2448 vs 2445/2452).
   No measurable effect alone.
4. Gravidar thread: ~1,000 unseeded draws per frame with equal counts; per-unit
   keying by saved ID converges the stream (no measurable world effect alone).
5. Event delivery order: ties in the due-event schedule break by heap address;
   02b712e reorders each batch by (time, saved ID). Works (0 failures).
6. Event rows (03a3a7e) located the first divergence: identical Gravidar scan
   events stamped with the load time on one client and tick 1 on the other.
   Causes: the Gravidar thread's TLS game-time copy and ungated Gravidar
   passes in boot phases 1-2 racing the first gated frame. Fixed by
   native_gate_gravidar_time_sync (7a6b4bb, 0c8a9ff, 5dc8dfe). Tick 1 is now
   identical on both clients (world hash and every delivered event).
7. Per-script RNG streams (2e03764): every AI script/MD cue entry draws from a
   stream keyed by owner saved ID. Shared sim-thread draws drop from thousands
   to 4-98 per frame; joined script keys have identical draw counts. Tick-60
   divergence 175-252 (S01/S02) versus 309-327 without it (T07/T08).
8. Gravidar sector order (d724118, 5c0e5e4, 4612ab5): the same AI scripts ran
   one tick later on one client because Gravidar Init orders its sector list
   by object address and Run scans a tenth of it per pass, so the load pass and
   every pass scanned different sectors. native_gate_ai_schedule with
   native_gate_gravidar_load_pass (hold Init's load pass until gated frame 1)
   and native_gate_gravidar_sector_order (scan in saved-ID order; one
   load-created sector, cluster_black2_sector01_macro, keyed by macro and
   parent) give identical Gravidar unit counts per tick. Without the order fix
   H02 diverged 231 objects at tick 10.
9. Pathing bank parity at admission is equivalent state (indices only); not a
   divergence source (1fc0710 makes the stamp hash bank-relative).
10. Boot phase 2 runs exactly two event passes and one universe update; its
   first AIDirector::Move raced ungated threads. native_gate_boot_hold moves
   it into tick 1; native_gate_md_timed_rng keys MD condition checks called
   directly from MDScheduler_Update/Cue_EnterWaiting/Cue_RaiseCueEvent
   (e0f5bb9). Tick-0 script keysets and draws become identical.
11. Full stack (F01): tick 0 scripts identical, tick 1 events identical,
   Gravidar identical; divergence 47 objects at tick 10 and 125 at tick 60
   (lean baseline 281-387 and ~1,750-2,000). First remaining difference: MD
   faction-goal cue instances at tick 1 (contrib/ferrite-census-mdorder).

12. MD resume delays (f94d653): loading re-rolls the random delay of every
   cue whose delay was pending in the save (Cue_ResumeAfterLoad 0x1115960,
   call 0x1115bad -> EvaluateRandomRange 0xc58da0) outside any keyed scope,
   so faction managers and goals started at different ticks. The opt-in
   native_gate_md_resume_rng draws them from a cue-keyed stream: 263 delays
   with identical key/draw/delay sums on both clients and across runs.
   Q01/Q02: script entries per tick nearly identical (847/850, 2911/2910);
   divergence 25-34 objects at tick 10 and 55-76 at tick 60.
   First remaining difference: StartTravelModeEvent subsets at tick 2.
13. Travel mode (c2ce18f): Agent_UpdatePathing 0xe8f250 decides travel mode
   from the formation leader's waypoint flag, which the leader rewrites in
   the same pathing pass on another job thread. native_gate_travel_determinism
   runs pathing batch jobs inline on the pathing thread in batch order (about
   15-25 ms per frame). V01/V02: one-sided travel events at tick 2 drop from
   104/72 to 6/3 and 3/1; batch order hashes identical across clients and
   runs; divergence 28-41 objects at tick 10, 55-73 at tick 60.
   Next lead: AI Wait deadlines re-rolled on import (pilot 80d54 move.idle
   runs at tick 1 on one client and tick 4 on the other).
14. AI Wait restores (dbd1f0f): AIDirector_Import 0x1069000 reattaches every
   blocked Wait (WaitAction::Reattach 0x10a50d0, call 0x1069bf9); the wait
   keeps no saved deadline and re-evaluates its random duration from the
   loading thread's natural stream. native_gate_ai_wait_rng keys all 18,943
   restores by saved owner, script/version/slot/PC and saved start time.

15. Hazard region damage (static analysis; live check pending): big-BW
   (180), big-BS (300), big-BS2 (240) and cam-CamB (300, no war) diverge in
   the health domain only for the same 357 objects, cam-CamA not within 600
   ticks: every ship of sector 0x7a5 (cluster_32_sector001, attention 2)
   plus the surface elements of its XL carriers; the save lists them as
   attacked by the sector ("hitbyareadamage"). Script draws and order match.
   U::Region::Move (slot 674, 0x767410) updates its DamageFields (slot 8,
   0xee16a0): a pass damages the zones' objects in proportion to the time
   since the last pass and sets the next pass to now + 1 s + a [0, 0.1 s)
   jitter from the shared sim-thread TLS word, mid-walk. One shifted natural
   draw moves the next pass by up to six ticks; every later capture then
   differs. native_gate_region_rng ('key' / 'observe') runs each
   Region::Move on a stream keyed by tick and saved region ID (vtable slot
   swap, stop reason 93) and logs one REGION_RNG_ROW per pass;
   census_scripts.py joins passes by region, field and rank.

where the zone sits (the G1o group's origin) depended on thread timing.

MoveWorker to the smallest request by (sector key, position). Queued as
long-L23 and full-G2.
