IMPORTED-WORLD CROSS-PLATFORM DIAGNOSTICS - FIELD MAP AND OFFLINE CONTRACT
27 October 2026

Scope
-----
Source audit: Windows345a780; Linuxd9eb06e. This defines additional read-only
diagnostic domains. It does not change x4-portable-fixture-v1, its12-actor frame,
strict comparison, permit rules, selected gameplay scenario or existing hashes.
No new hook, engine memory write, native artifact or game run is part of this
proposal. Tools/schema/parser/offline adapter work can proceed independently;
native capture integration requires a separately reviewed ownership boundary.

Why the Windows world roots cannot be portable roots
--------------------------------------------------
WORLD_IMPORTED_1 appends native class RVA, flags and parent to EVERY domain.
Motion also hashes controller RVAs and Windows-specific dock/getter encodings.
Timing includes attention, refresh cursor/gates and native bank timing bytes.
Some detail fallbacks intentionally retain opaque bytes for Windows diagnosis.
Those values cannot be copied into a cross-platform contract. Existing roots
remain useful and unchanged for their original Windows-to-Windows comparison.

Proposed additional diagnostic contract
--------------------------------------
Use a separately versioned imported-world diagnostic stream with a header binding
snapshot/content digest, exact ordered saved-ID inventory digest/count, capture
stage, tick/receipt boundary and game-time bits. Platform build/layout proofs and
physical selectors are local provenance, not canonical state. Compare state only
at the same proven stage/tick. Keep the strict portable frame as independent input.

The inventory is a fixed declared cohort from the immutable import capture; it
must not silently shrink to the currently supported classes or twelve fixtures.
Records are strictly saved-ID ordered. Bound the initial common cohort to524288
entries, rows to4096 bytes, identifiers to63bytes and reported differences to128;
excess input is an explicit refusal. Native allocation/capture time still needs
measurement and review; these bounds are not a performance claim.

Every inventory ID gets one identity/capture result plus all five domain results:
1. Entity: verified imported/live identity; supported semantic class, macro and
   true owner when known. Generic live identity does not imply class coverage.
2. Topology: saved parent ID only for supported layouts. Native null is explicit;
   an unmapped nonzero parent is unresolved_reference, not canonical zero.
3. Motion: active/other local position and three basis vectors, plus separately
   named ref_b0/ref_b8 saved IDs, only under the Navigation lifetime contract.
4. Health: stored hull binary64 only. Shield coverage stays unsupported.
5. Timing: explicit unsupported_layout for per-object timing in the initial
   intersection. Global game time belongs to the capture header; real/unpaused
   clocks are local hold guards, not substitutes for per-object timing coverage.

Each domain records supported field coverage and a bounded status from a closed
set: supported, unsupported_class, unsupported_layout, unresolved_import,
unresolved_runtime, missing_import, unresolved_reference, ambiguous_identity,
read_failed, changed_during_capture, not_captured. Unknown state carries no
invented value or raw native byte blob.
An actual missing imported object requires distinct registry-lifetime evidence;
it cannot be inferred from any generic read error or a zero import-map value.

Hash each typed domain record with schema/domain separation, savedID and explicit
coverage/status. Sort savedID+rowSHA pairs into separate domain roots. Preserve
the corresponding typed records for bounded per-ID first-field differences.
Report inventory and per-status census, supported counts, known-value differences,
coverage differences and missing IDs. Matching unsupported markers may yield
matching diagnostic roots but NEVER semantic equality or complete coverage.
Zero comparable records yields unknown, not success. Sparse deltas require a
complete initial inventory/root and an explicit terminator; otherwise refuse.

Offline implementation and review sequence
------------------------------------------
First implement the closed schema, pure streaming encoder/parser and comparator
under tools/dev with independent encoding goldens. No runtime import from the
game adapter. A pure X4IMP1 reader can validate Linux saved/runtime uniqueness
and preserve unresolved entries without claiming current presence. A separate
adapter can consume already validated portable actor rows for their supported
subset, marking every other cohort record not_captured. It must not fabricate
broader state coverage from those twelve rows.

Tests must cover IDs beyond12, shuffled/duplicate/missing identities, aliasing,
null versus unresolved references, finite exact float bits/signedzero, changed
bank roles, every domain/field/status mutation, all-unsupported and empty subsets,
snapshot/stage/tick mismatches, truncated records/terminators and bounded output.
No diagnostic result may set session_pass or bypass an existing strict failure.

Only after that contract is reviewed should native adapters reuse the existing
import copies and joined-main reads for a broader selected ShipSmall cohort.
Unknown classes remain in the inventory. Adding generic topology, shields,
velocities or per-object timing requires additional exact Linux and Windows
field/owner proof. No full-world gameplay parity follows from either12 fixtures
or equality of this deliberately partial imported-world diagnostic.

Implemented offline contract
----------------------------
tools/dev/native_world_portable.py implements x4-imported-world-diag-v1.
tools/dev/native_world_portable_adapter.py provides the retained X4IMP1 reader
and an adapter from the unchanged, independently validated strict portable frame.
No runtime, C, Rust, gate, transport, permission or protocol source changed.

The stream is ASCII JSON Lines: exactly one {"header":...}, one {"row":...} per
declared saved ID in increasing numeric order, then one {"footer":...} and EOF.
Each complete line, including its newline, is bounded to4096bytes. Duplicate
JSON keys, unknown fields, oversized/deep malformed input, premature EOF, extra
rows and missing/repeated terminators refuse. The encoder writes the footer only
after the entire declared inventory; an exception leaves an invalid partial file.
The CLI exclusively creates a fresh output path and never replaces old evidence.

Header fields: schema, source, snapshot_sha256, content_sha256, cohort_sha256,
cohort_count, stage, tick, game_bits. stage is exactly joined_main_pre_tick;
other capture stages refuse. tick is u64, game_bits is a finite nonnegative
binary64 encoded as16lowercase hexadecimal digits. source is windows/linux/offline
and is local provenance, excluded from canonical root context. All other header
fields must agree before comparison. The adapter binds content_sha256 to the
existing strict frame's exact contract digest, including snapshot/stock/fixture
content. Parsing cannot independently prove that a producer owned this boundary.

Each row contains saved (nonzero full u64 as16lowercase hex), identity and domains.
The complete identity status set is live, unresolved_import, unresolved_runtime,
missing_import, ambiguous_identity, read_failed, changed_during_capture,
not_captured. Non-live identity requires all five domain statuses to match it;
no semantic payload is accepted. A live but unclassified object can retain
unsupported_class without inferred parent, hull or transform fields. Every
domain result has exactly status/value; any unsupported status requires null.
Supported fields require a supported entity class, specifically ship_small.

Exact supported domain payload keys:
  entity: class, macro, owner (existing portable identifier restrictions).
  topology: parent_saved (full saved ID, native null is0000000000000000).
  motion: controller=navigation, active, other; each bank has transform (12finite
    binary32 hex words, position followed by three basis vectors) and references
    (two full saved IDs, native+b0 then+b8). Physical selectors are not encoded.
  health: stored_hull_bits (finite nonnegative binary64 hex, signed zero retained).
  timing: no supported payload in this version; supported timing refuses.
Nonzero semantic references must belong to the fixed cohort; a producer lacking
that translation must use unresolved_reference rather than guessing null.

Canonical JSON J sorts object keys, has compact separators, escapes non-ASCII
and rejects NaN/Infinity. Valid typed payloads contain no JSON floating numbers.
The following hash prefixes include one literal zero byte where written \0:
  cohort = SHA256("X4WDIAG1-COHORT\0" + each savedID as little-endian u64).
  row[D] = SHA256("X4WDIAG1-ROW\0" + ASCII(D) + "\0" + savedID_LE +
                  J({identity: row.identity, result: row.domains[D]})).
  root[D] = SHA256("X4WDIAG1-ROOT\0" + ASCII(D) + "\0" + J(header without source)
                   + each savedID_LE + binary row[D] digest in cohort order).
The footer contains exact row count, all five roots, every identity-status count,
and every domain-status count including zeros. The reader reconstructs each byte
domain and compares the full footer; advertised roots are not trusted.

compare() consumes both complete streams before returning stream_valid. This
means syntax/cohort/roots are valid, NOT native capture or session acceptance.
Per-domain counts separately retain comparable supported rows, known value
differences and coverage differences. semantic_equal is true only when the entire
cohort is supported and equal for that domain, false for a known semantic value
difference, otherwise null. supported_subset_equal is null when there are zero
comparable rows. root_equal and coverage_equal remain distinct diagnostic facts.
Per-ID differences include identity/status or the first differing supported
field and exact values; output truncation never stops validation of later rows.
There is no session_pass/permit result or runtime import of this implementation.

X4IMP1 records bind the complete retained import inventory, not live world state.
The reader accepts exactly the8-byte magic X4IMP1\0\0, little-endian u64 count,
then count pairs of saved/runtime u64 and EOF. It rejects zero, duplicate or
unordered saved IDs, aliased nonzero runtime IDs, truncation and excess counts.
Runtime0 remains unresolved_import. All64identity bits are retained. The common
bound is524288; a larger Linux inventory explicitly refuses this version.

The adapter never filters the declared inventory to supported actors. It refuses
a cohort that drops any supplied import record; any declared ID missing from the
local map gets missing_import. Selected strict-frame actors require a unique
nonzero imported mapping. Every other mapped object gets not_captured, because
the historical import alone cannot prove its current registry generation or
class. Parent/reference IDs can therefore name explicitly uncaptured cohort
members without pretending those members have captured semantic fields.
The current actual export adapter is X4IMP1 from Linux; no Windows full-runtime
map or broader native memory sampler is fabricated by this offline change.
