Original, candidate and write lifecycle

The shared bounded XML helper copies text and structural bytes, evaluates the
independently authored integer C math into private words and calls the original
XML reader once with its unchanged two arguments. A guard/capture/math/STOP
refusal still executes the original once and performs no candidate write.
Only a normal return with unchanged serial, owner, module, manager, selectors,
input transcript and exact Agent/bank can reach the writer.

The private plan is used synchronously by that invocation only. Under the same
lock used to publish rotation STOP, the writer rereads the entire 416-byte bank
twice, compares all nine before-words against the plan, checks writable pages
and rechecks native ownership. It then stores only the nine aligned 32-bit basis
words. A full-bank post-read must equal the prior bank with precisely those
36 bytes substituted. All fourth lanes, position, references, flags, timers and
unsupported fields must remain unchanged. Byte-identical ABA is not detected by
the transcript; the pinned synchronous XML/Agent lifetime and native exclusion
remain essential. No replay or atomic snapshot claim is made.

STOP participates in the lock even before configured is published, closing a
configuration/first-CAS race. A write admitted first may finish before STOP; a
STOP admitted first prevents the write. No original is called with this lock
held. Code restoration is serialized through the same lock and preserves a
foreign word. A page/cache/protection/ownership error is retained. If a store
faults or another participant changes the bank, the world is failed: there is
no rollback or all-or-nothing-store claim.

Compiler-generated Windows __try/__finally scopes record abnormal completion,
close their own Load/rotation counters and propagate the exception. The gate
build adds -fms-extensions for these scopes. Normal-return receipts and native
after-reads are not run from an abnormal cleanup. Owned executable tests include
valid registered unwind metadata for synthetic callers; an isolated exception
helper alone was not considered proof of the nested wrapper path.

Independent-review correction: OS cleanup obligations

The original source-only revision f110fc0 could restore the original code bytes
but lose a failed page-protection or instruction-cache cleanup obligation. Its
first error remained sticky and blocked acceptance, but a later clean restore
could leave an original-byte page RWX or fail to retry the cache operation. No
native session used that revision.

The follow-up separates byte ownership from protection_pending/flush_pending.
The prepare-time RX protection remains immutable; a temporary RWX page after a
failed repair never becomes the next target protection. Cleanup retries both
pending operations even after the original-byte CAS clears ownership. A foreign
word is never overwritten, including when permission/cache repair is still due.
Preparing again cannot erase a pending obligation. Pending work prevents owned
publication and terminal restoration, and successful cleanup never clears the
failed-session diagnostic.

The actual owned-page regression matrix covers both sites, install and restore,
and transient/persistent protection/cache failures (sixteen cases), plus foreign
words with and without retained byte ownership. The focused suite now passes
41,904 checks, including proof of actual RX restoration, retried cache work and
sticky failure after repair. These are offline tests of the production CAS and
cleanup functions; the original failed revision remains available for review.
