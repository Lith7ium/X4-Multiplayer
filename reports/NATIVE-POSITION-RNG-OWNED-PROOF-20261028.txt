SELECTED POSITION RNG: OWNED CALLER PROOF AND CLEANUP CONTRACT
28 October 2026 | supplement to frozen proposal 2a9e395

SCOPE AND RESULT

The unchanged production Position wrappers pass 6,805 always-on checks in an
owned-memory executable built with -O2 -DNDEBUG. The previous 6,772 checks are
retained. The additional checks establish the proposed maximum/result-scratch
locations and independently construct the 260-byte semantic key and scalar
three-draw vector. Two deliberately wrong offsets fail with exit 42. This is
not a game run, an engine-function execution, or proof of Linux math parity.

The test reads the pinned executable only for image verification. Its caller
bodies are authored assembly with native-shaped frames, not copied executable
engine bodies. It uses the actual production wrapper, incoming-return-slot
capture, guarded reads, exception handling and existing thunk/patch fixtures.

The first authored caller has c58da0's seven pushes and 0x100-byte frame; it
sets RBP from the incoming RSP as in the pinned prologue. The maximum Value is
at RBP-0x79, equal to the sampler's true incoming T+0x78. The second authored
caller has c59b00's 0x58-byte frame, initializes its result scratch, and passes
its actual address in R8. The range body records that incoming R8. The wrapper
test requires it to equal T+0x178, rather than accepting a merely plausible
stack address. The scratch tag/payload are zero and its ignored padding has
a distinctive marker; the maximum/difference are tag 5, float 50000.

Both ordinary return and a real foreign SEH exception pass. The inherited
four-site tests retain full RAX, XMM2, fifth stack byte, opaque XMM0, foreign
scope and original-once checks. The proof does not assert that the future RNG
intervention or its own finally has been implemented or tested yet.

REQUIRED CLEANUP PRECISIONS

This supplement resolves two ambiguities in the frozen proposal. It does not
alter its key, selected inputs, finite math paths or allowed Find compositions.

1. A pre-write refusal is different from an attempted seed store. The receipt
must distinguish prewrite_refused, write_attempted, applied/readback_confirmed,
restore_required, restored and debt. Under serialized admission, preserve the
caller state and mark write_attempted plus restore_required BEFORE attempting
the guarded store. Confirm the exact stored value by readback before calling
the scope applied. A faulting, partial or uncertain store must still enter
conditional restoration, even if applied remains zero. Only a path on which no
write was attempted may use the natural refusal path without restoration.
Unsupported restoration retains debt and a strict failure; it cannot borrow
another TLS location or claim that an unconfirmed write did not occur.

2. The outer finally runs after the generic raw outer-post capture and BEFORE
wp_outer_finish publishes completion or decrements the generic open count.
It executes outside wp_lock and runs even if post-capture, STOP, identity or
SEH checks failed. The raw scoped output is retained before restoration; the
separate receipt records both the actual scoped endpoint and restored caller
state. Abnormal cleanup uses only resident observer metadata and revalidated
TLS storage. It does not dereference unwound engine frames or suppress the
original exception. A successful restoration never erases the original error.

The reviewer accepts this bounded implementation plan with these precisions.
Production code, bridge/parser joins, both explicit compositions, failed-write
cases and unchanged historical failures still require a frozen source review.
No new native game, artifact staging, or global RNG rewrite is authorized here.
