LOCKSTEP INPUT MULTIPLEXER: PILOT RECORDS, ORDERS AND HIT CLAIMS IN ONE BLOB
29 October 2026 | offline (LuaJIT/Python, synthetic clients, mocked gate; the
container codec also checked against the C functions); no X4 launched

WHY
Protocol 3 carries one opaque blob per client and tick (<= 240 bytes). The
probe's pilot adapter (wire source) and the player orders adapter each owned
X4LAN_NATIVE_INPUTS exclusively, so humans could not fly by wire and give
lockstep orders in one session, and hit claims (prediction work) had no slot.
The prediction agent defined the container in src/native/engine/
lockstep_hit_claims.h (input_mux_decode/encode); this work is its Lua side.

FORMAT (identical to lockstep_hit_claims.h; reasons identical)
  ''                       no input
  28 bytes, first 0x01     pilot record v1 alone (legacy form)
  first byte 0x50          player orders v1 alone (legacy form)
  0x4d 'M', 0x01, then sections kind|length|payload, kinds strictly ascending:
    0x01 pilot (28 bytes, first byte 1), 0x48 hit claims, 0x50 orders (first
    byte 0x50). A container with only pilot or only orders is refused
    (noncanonical): every content has one encoding, encode(decode(x)) == x.
Refusals: encoding (Lua/Python text check), too_long, pilot_length, channel,
version, truncated, order, section_length, kind, orders_channel, noncanonical.
Hit claim payload: count 1..8 + 26-byte claims (version<<4|kind 1 in/2 out,
flags 0, observe16, projectile key, target portable ID, point 3 x int16 in
1/8 m, little endian); refusals length, claim, point, identity, duplicate.
A pilot-only or orders-only session sends exactly the bytes it sent before.

MULTIPLEXER (X4LAN_NATIVE_INPUTS, owner 'mux')
Sections register by name (pilot, orders, hits) with an owner tag; only the
same owner may replace a section (a UI reload re-registers). An external
adapter that is not the multiplexer keeps the wire to itself (contract
unchanged), and a section cannot register then.
Each section keeps the adapter contract for its own payload:
  apply(tick, inputs, clients, slot) -> receipt or nil   inputs[k] = slot k's
    payload of this section, '' when absent or the blob was refused
  proposal(tick, budget) -> payload or nil   budget in hex characters
  refused(tick, reason)                     optional; 'overflow'
Admission (every client, identical blobs): each slot's blob is decoded; a
malformed blob, or one with a section nobody registered, yields no sections
for that slot (INPUT_MUX_REFUSED tick= slot= reason=). The fold
  INPUTS_1|<tick>|<k:sections or - or refused_<reason>,...>|pilot:<slots>/
  <bytes>|<receipt or ->|hits:...|orders:...
(registered sections only, wire order) is the adapter result the probe adds
to the declared digest; orders still contribute PORDERS_1, hits HITS_1, the
pilot receipt stays in PILOT_1 (gate.pilot_inputs_frame).
Proposal (local, deterministic): sections in priority order (default pilot,
orders, hits; native_gate_input_priority = {...}); each is offered the bytes
left after the container header (2) and the sections already taken (2 + its
length each), minus its own header. A payload above its budget is refused for
this tick (INPUT_MUX_OVERFLOW tick= section= bytes= budget=, refused callback);
later sections are still offered. Budgets with the default order: pilot 236,
orders 206 after a pilot (orders never exceed 120), hits 84 after a pilot and
a full orders blob (3 claims; 8 claims need 209). The orders adapter packs
only the commands that fit its budget and keeps the rest queued (no command
is lost); the hit carrier packs only whole claims that fit. Idempotent per
tick. A malformed local payload stops the session (local bug, fail closed).

HIT CLAIMS
native_gate_hit_claims = 'carry' registers K.hit_carrier: scripted claims
(native_gate_hit_claims_script = {[slot]={[tick]={{kind=1|2, back=0..8,
projectile=, target=, point={x,y,z}}}}}, observe tick = tick - back) ride the
wire; admission decodes them, reconstructs the observe tick as hit_stage does
(window 8, from tick 2) and folds HITS_1|tick|slot/index/in|out/observe/
projectile/target/point/carried|refused_far rows (log HIT_CLAIM). It never
applies a hit: the native staging/resolution of lockstep_hit_claims.h has no
Lua binding yet. Interface for that adapter: register section 'hits' with its
own owner tag, apply(tick, inputs) stages the payloads (gate call), proposal
(tick, budget) returns the claims that fit.

LIMITS
- Offline only; the native relay/gate treat blobs as opaque (no native change).
- Hit claims are carried, not applied (no native binding yet).
- The overflow rule refuses a section for the tick; the orders adapter and the
  carrier keep their queues, a third-party section must do the same.
- Blob decoding is strict: a peer that sends an unknown section or a
  malformed container loses all its sections for that tick on every client
  (with wire piloting the pilot module then stops on the missing record).
