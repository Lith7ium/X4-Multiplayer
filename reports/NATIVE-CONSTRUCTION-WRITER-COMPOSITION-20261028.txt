CONSTRUCTION RNG: ENABLED ACTOR WRITERS AND UNWIND COMPOSITION AUDIT
28 October 2026 | Source audit and owned-memory tests only

Evidence correction after 66f6f11
-------------------------------
The first private witness used assert.h without clearing NDEBUG under Zig -O2.
Those executions and their constant PASS diagnostics are INVALIDATED as test proof.
Their source/executable/output hashes remain in the PINS file, explicitly marked
invalid. They must not be cited as assertion-backed evidence. This was a harness
error; the source/config/image/trace checks were independent of those assertions.

The corrected private witness uses always-on CHECK, explicit per-writer reach
counts and nonzero process failure. Both exact source versions were rebuilt and
rerun: 137 checks each, all twelve writers reached, exit 0. A forced false check
and a semantic probe requiring the inner continuation to contain the restored
parent word both exit 97 on both executables. The latter fails at Flight, before
any successful result can be printed. These fresh runs establish the counterexample
below; they do not rehabilitate the invalidated executions.

Decision
--------
Proposal 1881319 must not enable constructor RNG on the strength of the accepted
observer cleanup alone. Ordinary construction 016 enables twelve actor-local TLS
RNG writers. Every one restores its borrowed RNG word only on normal completion,
including the range writer after observer fixes 834f2d5 + 74ced4a. An exception
caught inside Generate can therefore resume Generate with an inner actor stream.
An outer Generate finally runs too late to repair that continuation.

Keep the ordinary 016 option mask and native calls. The smallest defensible support
policy is narrow abnormal cleanup of all twelve enabled writer bodies, with their
transient context restoration, before allowing the new A/B writer. There is no
complete reachability proof that would justify excluding an enabled writer from
that policy. This audit does not assert that an exception occurred in 016, or that
all twelve writers actually nested inside its constructors.

Other RNG and composition inputs
-------------------------------
native_gate_seed_rng (bit 1) is enabled. path_release seeds the UI TLS word with
the admitted-frame seed after its Gravidar publication/join and ReleaseSemaphore.
That is a persistent frame baseline, not an actor save/restore scope. Do not add
an indiscriminate finally that restores it as though it were an inner actor stream.
Constructor reentry spanning such a frame boundary is unsupported unless separately
proved; the proposal's immutable execution tick/owner checks must remain strict.

native_gate_steering_init (bit 32) is enabled. flight_init_model uses a local uint64
state for two native FloatState calls and writes the existing model initialization
fields. It does not borrow TLS+318 and is not a thirteenth TLS writer. Parameters,
deadline refreshes, avoidance refresh, spline joining and other ordinary 016 options
retain their current native effects. Cleanup must not roll back those engine writes
or change native arguments to manufacture deterministic output.

NPC 47/48/49, solver 50, request 52 and docking 44/45 are off. Player, Wait and Find RNG
are not configured in 016. The observer prerequisite explicitly refuses NPC 47/48/49

coordinated with the NPC/faction reviewers. That work did not add writer cleanup.

Concrete caught-exception witness
---------------------------------
Private writer_exception.c includes the production gate and directly invokes each
actual writer helper with owned buffers and correctly typed fake originals. It
does not install hooks or execute an engine instruction. A normal case verifies
one original call and restoration. Each foreign-SEH case has this structure:

  outer constructor saves caller and selects its scoped word
    simulated native Generate calls the actual actor writer
      writer selects actor seed; original mutates it and raises 0xe0427777
    native-style inner __except catches that code and continues Generate
    continuation reads the still-active actor stream
  outer constructor finally restores caller

Both exact source versions reproduce all twelve cases: normal restoration succeeds,
the original runs once, the real exception reaches the inner catch, the continued
Generate word differs from its parent scoped word, and the outer caller word is
eventually restored. Weapon context/actor/slot also remain the child context after
the caught exception. In 74 the interrupt_current pointer is repaired by its new
observer finally, but TLS restoration remains inside its normal-return body.

Compiled with Zig 0.15.2 for x86_64-windows-gnu, -mcx16 -std=c11 -O2 -Wall -Wextra
-Werror -fms-extensions, linked with production portable_rotation.c, bcrypt and
ws2_32. The corrected CHECK macro is independent of assert/NDEBUG and calls
ExitProcess(97) on failure. Each of eleven writers reaches ten individual checks;
Weapon reaches thirteen including its three context fields. An additional fourteen
checks validate arguments, per-writer reach counts and the 137-check total. Both
executables exit 0 after all 137. --force-fail and --expect-restored both exit 97 in
both versions; their logs and hashes are retained separately from passing output.
The exact foreign exception call is RaiseException(0xe0427777,0,0,NULL). Each caught
record is checked for that code, flags 0x80 and zero parameters on this Windows
build. The RaiseException flags argument remains zero. The original flags==0
test assumption was rejected during revalidation and corrected to the actual
record; this does not change the TLS restoration predicate.
This is a production-helper/real-SEH counterexample,
not a synthetic replacement for the RNG writer and not evidence of an actual X4
exception. It does not certify a future implementation's ABI or TLS lifetime.

Required cleanup and support boundary
-------------------------------------
1. Add a narrow __try/__finally to the twelve writer bodies. Capture the exact
   selected RNG address, caller word and whether a seed was actually written.
   Establish the restoration obligation before the first write. Restore on normal
   and abnormal paths before an inner native handler can continue, even after STOP.
   Do not decide restoration from later stats.active or mutable option state.
   Retain same-thread/TLS lifetime checks; never write a replacement TLS block or
   an unproven stale address. Unsupported ownership loss must remain failed.
2. Preserve normal seed domains, schema 2 keys, actor identities, counters, selection
   timing and arguments. In particular keep fresh AI TLS selection immediately
   before ai_execute, as corrected by 74; do not hoist it across observers. Forward
   the native original once, preserving stack arguments and full range return.
   Normal after-samples require completed originals. Propagate exceptions unchanged;
   retain abnormal failure without manufacturing a successful after record.
3. Restore all three weapon context fields in the same finally. Keep74's range
   context/origin cleanup and compose it with TLS cleanup without double closure.
   The publication-level gravidar_in_frame guard also clears only on normal return;
   close that transient guard on abnormal publication before claiming the enabled
   Gravidar composition safe. Do not claim this fixes every engine critical section
   or all arbitrary native exception recovery.
4. The minimum support envelope remains the exact016 options and reviewed observer
   prerequisite. Solver/request scopes are disabled there. If allowed later, their
   own normal-only begin/end state in Flight/Agent, including excluded nested
   markers, needs independent abnormal closure. Keep NPC/player/Wait/Find writers
   outside this constructor composition until separately audited; a disabled flag
   must be proved through the actual configuration path.
5. Constructor admission must still linearize with STOP, use immutable A/B tokens
   and retain open/abnormal/ownership failures after cleanup. An admitted native
   call must finish once and restore on its owning thread. Neither STOP nor another
   thread may clear live obligations, unload code or reseed the live owner's TLS.
   Thread-local nesting must preserve the immediate parent's stream at each unwind;
   an eventual outer restoration is insufficient. Existing worker eligibility is
   not proof that worker activity is part of the selected UI scope.
   A constructor receipt must not report successful composition merely because its
   own original returned: bind the supported writer set to actual enabled flags
   and retain any child abnormal/ownership/cleanup failure through A/B validation.

Before acceptance, require actual production-helper tests for all twelve: normal
and propagated foreign exceptions; inner exception caught before A/B continuation;
two-level nesting, normal child/throwing child/throwing outer; exact original count,
arguments and range return; no-write disabled paths; same-thread TLS changes;
STOP before admission and during original; context/guard repair with sticky failure.
Deletion mutants must fail when any restore or weapon context cleanup is omitted.
Actual-image hook/ABI tests and retained016 parser failures must remain separate
from these owned-memory semantic tests.

If this closure cannot be supplied, refuse constructor RNG for the ordinary 016
combination. A reduced-writer variant would need a separately reviewed configuration,
registry dependency policy, fresh natural control and matching intervention using
that identical reduced baseline. It cannot reuse016 as its unchanged control, and
changing the registry guard merely to admit it would be an additional experiment.
