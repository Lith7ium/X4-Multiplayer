STANDALONE PORTABLE ROTATION C PORT - 28 OCTOBER 2026 UTC

Original arithmetic module and nongame verification only. No engine hook,
game-memory write, adapter linkage, staging, native X4 run or frozen-bundle change.
The previous mixed-native initial-state failure remains a failure. This port
implements the proposed common arithmetic, not either platform's native parser
or arbitrary native instruction grouping.

Interface and bounded ownership

src/native/engine/portable_rotation.{h,c} has no float/double operations, libm,
heap allocation, recursion, mutable global state or generated engine bytes.
All data-dependent arithmetic uses unsigned32/64 integer operations with checked
capacity; all scratch storage is automatic fixed-size storage.

x4rot_offset(orientation, attributes[3], output[9]) receives PITCH,YAW,ROLL.
Each attribute contains caller-owned const char*text, size_t length, unsigned
present. Missing is exactly{NULL,0,0}; present-empty remains distinguishable and
also defaults to+0. Nonempty text must designate length readable bytes. The
module scans exactly that length, with no implicit NUL scan. The strict grammar
and256-character bound match the reviewed Python reference.

ABSENT orientation returns KEEP_NATIVE=1 without touching output; it does not
invent identity orientation for the six saved offsets lacking rotation. EULER
orientation returns OK=0 only after all nine stored basis-vector words are ready.
All other results leave the entire caller output unchanged: UNSUPPORTED=-1,
OVERFLOW=-2, CAPACITY=-3. There is no native fallback after unsupported input.
The output contains v0.xyz,v1.xyz,v2.xyz only; no position, fourth lane, flag,
reference, XML pointer, engine object or world state is accepted or modified.
Caller validation of real XML memory/lifetime remains a separate integration.

Integer capacity argument

Each big integer has40 unsigned32 limbs (1280 bits), plus a bounded used count.
A256-character decimal coefficient has at most851 bits; the largest additional
binary32 rounding scale is149 bits, so parser temporaries need at most1000 bits.
Denominator construction and comparison shifts also fit that conservative bound.
A finite binary32 radian scaled by2^384 needs at most512 bits. Nearest-quadrant
division and its exact product fit well below1280 bits; the residual is checked
against half the pi/2 divisor. Its magnitude is below2^384. The series's largest
term magnitude is2^384, so term*residual^2 is below2^1152:36 limbs suffice, with
four extra limbs retained as checked capacity headroom.

The series quotient is exact: first divide the full integer product by the
small factorial step, retaining its remainder, then apply the768-bit nearest-even
shift. A nonzero division remainder contributes a sticky bit at an exact shift
tie. This preserves the Python recurrence rather than introducing an earlier
rounding. The pi/2 limb array is generated from the original Machin-series oracle
and compared back to it in every test build. It is not a copied engine table.
The128-term convergence guard returns CAPACITY if unexpectedly reached.

GCC13.3 -O2 stack-usage output reports the largest individual frame1824 bytes
(x4rot_sincos). The deepest listed public offset->basis->sincos->rounded_divide
->shift_right path totals3296 bytes of reported static frames. This is a measured
compiler configuration, not a universal ABI stack guarantee. No path recurses.

Reproduction and remaining gate

Run tools/dev/check_portable_rotation_c.py with --cc gcc on Linux or --zig pointing
to the existing0.15.2 compiler on Windows, --samples 100000,
--census pointing to the private saved-navigation census, and --report under.local.
Use --compare with the other host report to enforce source/count/output equality.
Private final evidence: .local/portable-rotation/c-{windows,linux}-final.json.
Generate the sanitizer fixture with tools/dev/make_portable_rotation_fixture.py;
compile portable_rotation.c plus test_portable_rotation.c using
-fsanitize=address,undefined -fno-sanitize-recover=all and pass the fixture path.

The sampled tests do not establish correctly rounded trigonometry for every
possible finite input. No native import ABI/lifetime/publication integration or
gameplay acceptance follows from them. The next distinct review is the bounded
XML/candidate-output helper and exact owned engine call/return integration,
preserving all non-basis bank bytes. Only a future reviewed two-native run can
establish corrected frame0 equality and subsequent lockstep behavior.
