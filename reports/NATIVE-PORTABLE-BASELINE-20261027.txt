Portable mixed-native baseline — implementation in progress

This is preparation for actual Linux X4 and Windows X4 sharing one bounded
zero-command fixture. No mixed native gameplay result exists yet. The prior
Windows/VPS relay and Linux clock/no-op results retain their separate scopes.

The closed x4-portable-fixture-v1 schema covers exactly twelve saved ShipSmall
objects: original fixture slot, saved identity, macro, true owner, parent saved
identity, stored hull bits, and active/other local navigation transforms and
saved references at b0/b8. Four xyz vectors contain position then three basis
vectors; padding and platform addresses never enter the shared bytes. Both banks
are role-relative; the other bank is not claimed to be the previous frame.
Shields, velocities, navigation flags, AI, RNG, weapons, cargo, economy, missions,
new/destroyed objects and other components are explicitly unsupported.

All fields retain exact IEEE bits, including negative zero. A complete frame
binds the contract digest, completed tick, native game time, original calls and
returns, and two ordered zero-command receipts. Counts must equal the completed
tick at the joined main pre-FrameTick boundary. Platform diagnostic hashes and
real-time epochs remain separate. An early load observer result cannot be used
as this boundary's tick zero.

Windows native transport update (27 October)

An explicit portable_transport configuration now sends NGP directly from the
existing joined main barrier. It requires Windows slot1, the exact world-identity
option alone, the closed twelve-ship contract and zero commands. Legacy NGSTATE2
remains the default. There is no new engine hook or Lua-driven frame permit.

The participant sends immutable captured bytes, with a separate SHA256 diagnostic,
and repeats HELLO/STATE while waiting. Every retransmission and accepted GO or
STOP first rereads the actual native sample and game/real clocks. A change refuses
admission. Stale and foreign messages cannot grant; future grants and nonzero
commands fail. Artifact declarations still require independent runner verification.

The boot watchdog and first captured-frame wait use the explicit bounded startup
allowance; later frames retain the shorter runtime timeout. The coordinator's
absolute startup budget continues until first GO, even if one game loads earlier.
Repeated HELLO messages cannot extend that budget.

Cancellation and continuation claims share a lock. If cancellation wins, the
suspended continuation waits for the restoration attempt to finish before it is
counted or called. If the continuation claim wins, later cancellation may overlap
it. No lock spans the original native function, which can synchronously reenter
stop. Restoration completion does not conceal ownership failure: the failure
remains explicit and cannot produce a successful terminal receipt.

Every exit from the joined gate uses the same original-call/return accounting.
Successful STOP requires all requested frames, one final outside-admission
continuation, matching call/return counts, restored main/dt/import hooks and zero
failures. The socket stays open only for bounded DONE retransmission and exact
CLOSED acknowledgement. Cleanup exchanges socket ownership once. Failed partial
Lua setup and common-loader update errors request native cancellation.
The common loader accepts only Linux's private45841 or the released Windows
disposable lanes45850/51/53..58, with an exact configured save path and matching
profile suffix. Windows45841/42 remain protected. The source bytes are common
across platforms; the runner supplies the separately verified owned profile.

The transport test compiles the production gate and reader against owned memory
and uses actual loopback UDP. It covers state/clock mutation, stale/future/nonzero
permits, cancellation during native rereading, both stop/continuation orderings,
startup versus runtime timeout, terminal packet loss, count mismatch and three
restoration ownership failures. A production Python coordinator separately checks
the emitted bytes and terminal exchange. These remain synthetic-engine tests.
Actual-image refusal/CAS/forwarding checks and focused Python/Lua tests also pass.
No mixed-platform native gameplay or independent player-input acceptance follows.

The optional cancel addition changes the common loader digest. Future native

Windows terminal observation (offline validation)

The common loader now invokes an optional backend observer from its existing
onUpdate callback, including after a loader error. It adds no readiness condition
or game getter. The Windows observer reads native portable_status afresh and emits
at most one bounded PORTABLE_NATIVE TERMINAL row. Run, slot, contract, snapshot
and declared agent digest bind the row to the owning runner's expected artifacts;
the runner must independently associate the log with its actual PID/start and
loaded DLL. A logged digest is not proof of the loaded module.

Success requires native closed=1, draining=0, terminal restoration, zero failures,
reason1, exact configured limit and completed/issued ticks, and frames/calls/returns
equal to limit+1. Active or draining status is not a terminal receipt. An inactive
native refusal produces failure even at frame0 or with portable failures=0;
its counters can still describe an unfinished exit and never establish completion.
Nil or malformed status cannot become a synthetic receipt. ERROR and CANCEL
remain fatal. The new optional seam changes the shared loader digest, requiring
new common manifests on both platforms.

The native status accessor adds active/reason/issued/completed. After native stop,
it can read only owned diagnostic state from the loaded UI thread without adopting
that thread or granting generic control authority. This covers the frame0 case
where issued remains0 and ordinary UI adoption is intentionally unavailable.
Closure is published after the final original return and CLOSED acknowledgment;
Lua may observe it on a subsequent update after the main hook has been restored.
If X4 exits, reloads the adapter after stop, or supplies no such update, no success
row is invented: the owning runner must refuse missing terminal evidence.

Production C transport tests exercise status from a distinct real test thread
through successful closure, frame0/clock/ownership refusals, cancellation and
startup timeout; UI ownership remains unchanged and stop authority is refused.
LuaJIT tests cover delayed/nil/draining status, exact counts, duplicate suppression,
malformed data, unchanged load admission and observation after cancellation.
These are synthetic-engine/real-loopback checks, not a native game result.

The Windows wrapper now adds independent process/module identity evidence. Before
the released launch it hashes the exact EXE and DLL through read-only handles
that deny write/delete sharing, retaining them until owned exit. It duplicates
the released runner's existing process handle, checks PID/creation time and
image path, and requires membership of that runner's existing kill-on-close job.
Process creation must follow acquisition of both artifact leases. During normal
released polling it checks the actual loaded DLL path and PE image size, rejecting
foreign same-name modules, changed identities or disappearance. It does not open
processes by PID, write memory, launch or stop processes itself.

Normal collection records signaled exit on the same process handle before closing
the artifact leases and allowing released restoration. Missing module/job/exit
evidence or any identity error makes the wrapper's session finish fail even if
the original pass trigger matched. Original queue, launch, poll, collect, restore,
job cleanup and failure reasons remain in place. Five real Windows nongame child
tests pass, including wrong PID/job/path, absent module, premature exit checks,
retrospective attachment refusal and actual write/delete denial while leased.
Eight wrapper tests pass on Windows and WSL; those five Windows handle tests are
explicitly skipped under WSL. No X4 game was started for this validation.

Failure-path review also requires lease release before restoration when launch
