LIFECYCLE, TLS AND EVIDENCE CONTRACT

A separate explicit manifest/config opt-in requires Wait, Action and Values
observers already configured. Default off changes no byte of natural execution.
Configuration and closure use serialized admission/rechecks. Selected ordinal0
is single-use; a second qualifying attempt is a fatal duplicate, not ordinal1.
The ledger is per canonical owner/order/action; cross-thread global order is not
a comparison key. All candidate entries participate in nested-scope detection;
selected-to-foreign-to-selected cannot borrow an enclosing selected scope.

After every identity/phase/declaration/candidate/anchor guard passes, reserve the
receipt and single-use scope. The final closed/state/TLS checks and seed write
share the closure lock, preventing a write from beginning after STOP. Store the
caller state and write the seed once, then release the lock before original.
Call the native function exactly once. No lock is held across original.
Refused/unselected paths call original once
without writing or restoring TLS. Conflicting existing RNG scopes must refuse;
the first implementation must test nested Wait/Action scopes explicitly.

Use a production __try/__finally around that single call, now that the integrated
compiler enables -fms-extensions. On normal return retain scoped RNG output and
exact nested assignment; in finally revalidate the current TLS pointer before
restoring its original caller state, clearing only this scope's marker and
releasing its admission. Restoration remains necessary after STOP, but the
overlap is fatal evidence. Do not issue a new seed write after closure.
Postcondition/identity/STOP failures remain fatal even if caller restoration
succeeds. An unseeded path never restores. If the current TLS cannot be validated,
do not write through a stale pointer: retain fatal incomplete-restoration evidence.
On abnormal termination, finally marks this seed receipt incomplete/abnormal and
attempts only the same verified TLS restoration plus local marker/admission
cleanup. It must not read any borrowed command/Action/candidate/order object or
invoke ordinary after-observers. A narrowly guarded observer write failure must
not replace the original engine exception, which continues to unwind. No order,
command, Value, position or deadline rollback is attempted.

This proposes cleanup of the new RNG scope only. Existing outer Action/Values
wrappers do not yet balance every abnormal exit; their open scopes remain strict
failures. A synthetic RaiseException test can establish the seed finally path;
it cannot establish complete engine exception recovery or valid enclosing trace.

The native return is opaque full RAX and must be preserved. Keep the owned hooks,
resident forwarders, protection/cache failure accounting and STOP open scopes.
Add separate intervention receipts joined to the existing parent/candidate event:
anchor status, ordinal, key digest, caller-before, seeded-before, scoped-after,
restored-caller, applied/refused/restored/errors. Preserve original raw snapshots.
Do not describe restored caller state as a natural RNG advancement. The scope
removes that draw from the caller's continuing stream; it does not align the
global RNG stream or freeze all AI state.
