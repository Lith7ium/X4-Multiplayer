Exact native-produced null witness
----------------------------------
The pinned d1c8a0 resolver returns its output address in RAX at d1cc55. On the
null-result path c6f927 -> c6f92e -> c6fb55 -> c6fb6a, no instruction changes RAX.
The existing 3872..3903 radius thunk forwards RAX into wrapper-only R9 before its
register-preserving absolute jump. The native three-argument c59b00 function
first accesses R9 by zeroing it at+9, before any use. Original arguments and the
opaque scalar return remain unchanged for selected, foreign and refused calls.

Let S be the actual native outer body's entry return slot. Five pushes and the
0x100 allocation leave the caller stack unchanged through the radius CALL.
The direct radius-wrapper incoming return slot T is S-0x130. The resolver local
at outer RBP+0x67 is S+8, or T+0x138. For the supported null path the reference
resolver is bypassed, so it cannot replace this local.

The wrapper obtains T directly with _AddressOfReturnAddress. It requires the
forwarded native pointer to equal T+0x138, the immediate caller c6fb6f, current
TIB bounds/alignment, exact active owner/descriptor/frame and a zero local before
and after the original radius call. It also requires completed outer return.
The recorded outer return word at T+0x130 is diagnostic and must remain stable.
It is not compared with be0bd1: entry hooking means the native body returns to
the owned outer observer continuation, while be0bd1 is the wrapper's caller.
There is no generic DLL-membership or guessed compiler-frame acceptance rule.

The same full native function pins remain mandatory. The original c6f7b0,
d1c8a0 and c59b00 bodies and relevant branch slices were independently checked.
Borrowed reads occur only on normal paths. Exceptional finally blocks touch only
